============================================================ 35. ASSET
NAMING, FILE PATHS AND USER UPLOAD GUIDE
============================================================

This is a mandatory planning deliverable. The user wants exact filenames
to assign to every image and video, especially all logos, and wants
correct paths in code.

Before implementation, inspect the supplied brand assets, the supplied
hero image, existing project images and the planned design. Then create
a complete Asset Naming Guide and Asset Inventory.

The guide must tell the user, in a simple table: - Exact filename to
give each image. - Exact filename to give each video. - Exact folder
where it must be placed. - What the asset is used for. - Whether it is
required or optional. - Recommended format and dimensions/aspect ratio
when relevant. - Whether a light/dark/theme-specific variant is
needed. - Whether the asset already exists or must be
supplied/generated.

Do not merely tell the user to upload “a logo” or “a hero image”. Give
the exact filename and exact folder path.

Use clear, consistent, lowercase, hyphen-separated filenames. Avoid
spaces, ambiguous names, duplicate names and random suffixes.

Suggested initial naming convention (verify against actual requirements
before finalizing the list):

BRAND IMAGES: - brand-logo.svg - brand-logo-dark.svg -
brand-logo-light.svg - brand-monogram.svg - favicon.ico -
favicon-32.png - apple-touch-icon.png - og-cover.webp

HERO IMAGES: - hero-background.webp - hero-background-mobile.webp (only
if a genuinely different crop is needed) - hero-decoration-01.webp (only
if required) - hero-decoration-02.webp (only if required)

PROJECT IMAGES: - project-[unique-id]-cover.webp -
project-[unique-id]-01.webp - project-[unique-id]-02.webp

TECHNOLOGY AND ILLUSTRATION ASSETS: - technology-[name].svg -
illustration-[purpose].webp - background-[purpose].webp

VIDEO ASSETS, ONLY IF ACTUALLY REQUIRED: - hero-background.mp4 -
hero-background.webm - project-[unique-id]-preview.mp4 -
background-[purpose].mp4

Do not require duplicate theme-specific copies if CSS filters or SVG
styling can safely handle the theme. Do not create unnecessary video
assets. The hero background image is already selected and must remain
the same composition in every theme. Ask the user for any missing
required assets.

After approval, create an asset manifest that maps every required file
to its exact path, for example: -
frontend/public/assets/images/brand/brand-logo.svg -
frontend/public/assets/images/hero/hero-background.webp -
frontend/public/assets/videos/hero/hero-background.mp4

These are examples; produce the final list based on actual design
requirements. Every code reference must match an actual filename and
verified path. Never guess a filename, rename a file silently, or leave
a broken reference. Test that all referenced assets load.

The user specifically wants to know only what names to give the assets
and where to place them. Make the asset guide simple to follow, with a
required-assets checklist and optional-assets checklist. Do not ask the
user to invent filenames.
